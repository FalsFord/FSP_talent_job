# EndPoint — интеграции FSP Talent

## Архитектура

| Компонент | Ответственность |
|---|---|
| React + Express | Интерфейс, прокси API и WebSocket; ветка endpoint-frontend |
| FastAPI | Авторизация, вакансии, назначения, решения, рейтинг, чат |
| PostgreSQL / pgvector | Данные платформы, снимки заданий, RAG |
| Redis | Рассылка сообщений между подключениями |
| ATS → Reqcore | Структурированный скрининг по критериям работодателя |
| GigaChat | Внешняя генерация; OAuth и ключи остаются в FastAPI |
| Judge0 | Изолированное выполнение алгоритмов |
| git-eval | Анализ GitHub-репозитория; выполнение кода отключено |

## Сценарий тестового задания

Работодатель назначает набор откликнувшемуся соискателю либо получателю предложения.
Назначение закрепляет состав, критерии и параметры заданий. Новый шанс создаёт новое
назначение с отдельным прогрессом. Активный набор повторно не создаётся.

Соискатель принимает задание или открывает его из чата; начинается общий таймер.
Алгоритмы решаются встроенным редактором. Отправка возможна только после прохождения
всех тестов текущим кодом. Для отбора и квалификации прикладывается GitHub URL,
включая ссылку вида /tree/branch. Набор отправляется один раз, затем исчезает из активных.
Истечение срока закрывает выполнение. Пропущенные задания не создают новых назначений.

Работодатель видит автора, вакансию, код, результаты тестов, время, память и Git-отчёт.
Низкий Git-score не скрывает прикреплённый репозиторий. Ошибка сервиса проверки — отдельный
статус, не провал кандидата. Сложность O(n) оценивается приблизительно, не является доказательством.
Кнопка «Проверено» сохраняет статус; проверенные решения доступны отдельной вкладкой.
Отозванные предложения исключены из списков проверки. Переход на этап записывается в чат.

## Вакансии, профили, файлы

В подборе и откликах выбираются опубликованные вакансии; редактор позволяет переключать
черновики и опубликованные. Удаление сохраняет снимок в `archived_vacancies`, данные компании
для старых предложений и переписки. Архив не восстановит вакансии, удалённые до его внедрения.

Аватарки и логотипы загружаются в файловое хранилище; браузер получает их через авторизованный
API. Резюме доступны согласно политике контактов. Незавершённая регистрация блокирует отклик
с объяснением недостающих шагов. Дневной лимит приглашений и cooldown пары удалены;
идемпотентность запроса сохранена.

## ATS, рейтинг и демонстрационные функции

ATS объясняет соответствие профессиональным критериям, окончательное решение принимает
работодатель. Критерии задаются вручную или на основе вакансии. GigaChat adapter:
`POST /api/internal/ats-ai/v1/chat/completions`, только Bearer внутреннего service token.
Фронтенд не получает OAuth-секреты. Бесплатность зависит от тарифа/остатка токенов GigaChat.

Ежедневные награды ограничены сервером; рейтинг виден работодателям. Достижения ФСП работают
в mock-режиме. Генерация отбора/квалификации стоит 10 единиц, единица = 2,5 рубля;
пополнение демонстрационное, без платежей. Хакатоны — исключительно UI-макет, PDF не отправляется.

## Основные добавленные API

| Метод | Путь | Назначение |
|---|---|---|
| GET | /api/workspace | Состояние интерфейса текущего пользователя |
| POST | /api/vacancies/{id}/assessment-invitations | Назначить набор / новый шанс |
| POST | /api/offers/{id}/assignment/start | Начать выполнение |
| PUT | /api/me/assessments/assignment | Сохранить / отправить набор |
| GET | /api/employer/submissions | Решения и отчёты |
| POST | /api/employer/submissions/{id}/reviewed | Отметить проверенным |
| POST | /api/offers/{id}/stage | Следующий этап и сообщение |
| DELETE | /api/me/vacancies/{id} | Архивировать и удалить активную вакансию |
| DELETE | /api/offers/{id}/chat | Скрыть чат только для текущего участника |
| POST | /api/me/files/{kind} | avatar, resume или logo |
| GET | /api/files/{id} | Авторизованная выдача файла |

Полный список и схемы: `/api/docs`. Существующая документация FSP и git-eval сохранена.

## Проверки

Тесты `test_company_github_attachment.py`, `test_assessment_retry.py`, `test_unlimited_invitations.py`
проверяют интеграцию в отдельной временной БД (нужны права CREATE DATABASE).
`test_tasks_core.py` проверяет правила платформы. Тесты внешних провайдеров требуют отдельной
настройки; ключи и пользовательские базы в репозиторий не входят.
