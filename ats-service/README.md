# EndPoint + Reqcore + Ollama

Используется официальный открытый архив Reqcore 1.5.0:
https://github.com/reqcore-inc/reqcore-old-snapshot
Исходный commit: `c3a1fa51e4dedeeaccb4d4c15164de912f793781`.
Лицензия исходного Reqcore — AGPL-3.0, сохранена в `../reqcore/LICENSE`.

## Как устроено

EndPoint FastAPI → закрытый Python-адаптер → Reqcore Nuxt → Ollama Qwen3 4B.
Вызовы используют **встроенные** `generateCriteriaFromDescription` и
`scoreApplication` из Reqcore, а не имитацию ИИ. Дополнительные маршруты
`server/api/endpoint/` защищены служебным токеном и не опубликованы на хосте.
Ключи и токены не передаются браузеру. Обработка модели локальная.

Отклики, критерии и снимки отчётов сохраняются в PostgreSQL EndPoint.
Reqcore работает отдельным сервисом с отдельной PostgreSQL. Его собственный
интерфейс и дублирование кадрового процесса здесь не подключены: работодатель
управляет откликами в EndPoint. Файлы резюме остаются в существующем хранилище
EndPoint; Reqcore извлекает текст PDF/DOC/DOCX своим парсером. MinIO предусмотрен
необязательным профилем `reqcore-documents`, для этой интеграции не требуется.

## Использование

В кабинете работодателя: **Отклики → выбрать вакансию → Настройки ATS**.
Базовая автонастройка берёт грейд, опыт, стек, формат и зарплату из вакансии.
**Автонастройка Reqcore** генерирует дополнительные профессиональные критерии
через локальную модель. Работодатель проверяет их, правит веса и сохраняет.
Изменение настроек запускает переоценку. Скачанный HTML-отчёт можно печатать в PDF.

Категории: «Подходят», «Нужно уточнить», «Явные расхождения».
При недостатке основных данных или ошибке модели отклик остаётся в «Нужно уточнить».
Для рекомендации «Подходят» нужно уверенно оценить не менее 80% веса критериев;
небольшие пробелы остаются явно отмеченными в отчёте. Низкий общий балл сам по
себе относит отклик к явным расхождениям только при полном покрытии критериев.
Автоматического изменения статуса на принят/отказ нет. Отчёт показывает основания,
сильные стороны, пробелы, модель и время оценки. Для явных расхождений требуется
достаточная уверенность либо прямо подтверждённое несоответствие грейда/опыта.

## Запуск

Из `backend` в PowerShell:

```powershell
../ats-service/setup.ps1
docker compose up -d --build ollama reqcore-db reqcore ats api
docker compose exec ollama ollama pull qwen3:4b-instruct-2507-q4_K_M
```

Модель хранится в отдельном Docker volume, переживает перезапуск.
Сборка использует локальные исходники `../reqcore` с адаптационными маршрутами.
В `backend/.env` находятся `REQCORE_AI_PROVIDER`, `REQCORE_AI_MODEL`,
`REQCORE_AI_BASE_URL`, `REQCORE_AI_API_KEY`, а также сгенерированные пароли сервисов.
Ollama использует NVIDIA GPU; для машины без NVIDIA нужно убрать блок
`ollama.deploy.resources.reservations.devices` из compose.

На этой машине Docker располагает примерно 4 ГБ оперативной памяти. При повторной
сборке Reqcore сначала остановите Ollama (`docker compose stop ollama`), затем
соберите Reqcore и запустите оба сервиса. Модель занимает около 2,5 ГБ на диске;
её не нужно скачивать повторно. Не удаляйте общие Docker volumes: там находятся
данные сайта и Judge0.

## Проверки

`tests/test_reports.py` в этом каталоге проверяет обработку неизвестных данных,
категории, конфигурацию и служебную авторизацию.
`backend/tests/test_reqcore_integration.py` создаёт и удаляет отдельную тестовую БД,
проверяет доступ работодателей, экспорт, пересчёт и сохранение человеческого
решения. В нём ответ ИИ подменён; живой вызов проверяется отдельно.
